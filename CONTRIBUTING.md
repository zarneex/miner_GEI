# Как участвовать

Репозиторий ведётся так: **`main` принадлежит владельцу** (`@zarneex`), наработки
всех остальных приходят **своими ветками** и затем «стакаются» (сливаются) в `main`.
Прямые коммиты в `main` от контрибьютеров не принимаются — так проще не потерять
рабочее состояние и откатить любую идею целиком.

## Порядок для контрибьютора

1. Форк или отдельная ветка от актуального `main`:

   ```bat
   git checkout main
   git pull
   git checkout -b feat/имя-кратко
   ```

2. Делайте изменения **в своей ветке**. Одна ветка — одна тема: поле ввода,
   тест, график. Не смешивайте правку UI и рефакторинг движка.
3. Проверьте, что ничего не сломано (см. «Проверка» ниже) и что в коммит не
   попали секреты.
4. Запушьте **свою ветку**, не `main`:

   ```bat
   git push -u origin feat/имя-кратко
   ```

5. Откройте pull request в `main`. В описании: что меняется, зачем, как
   проверено (команда + результат), какие файлы затронуты.
6. Владелец смотрит PR и сливает (или просит доработку). После слияния ветку
   можно удалить.

## Правила ветки `main`

- Только владелец репозитория пушит в `main` напрямую.
- История `main` — рабочее состояние: каждый коммит в `main` должен запускаться.
- Крупные изменения (новый раздел UI, переработка движка) — сначала ветка и PR,
  даже у владельца.

## Что коммитить нельзя

- `config.json`, куки, токены, свои кошельки, скриншоты с ними.
- `AGENTS.md` / `CLAUDE.md` (личная память проекта), `notes/`, `.idea/`,
  `__pycache__/`, `data/` — это в `.gitignore`.
- Бинарники майнеров и логи.

Проверка перед коммитом:

```bat
git status
git diff --cached
```

Если в диффе видно `krx…`, `sessionid=`, путь с именем пользователя — уберите.

## Проверка перед PR

```bat
set MINER_NO_AUTOSTART=1
python tools\test_credentials.py
python tools\test_night_toggles.py
python tools\test_governor.py
python tools\test_gpu_guard.py
python tools\test_cleanup.py
python tools\test_tray_close.py
```

`MINER_NO_AUTOSTART=1` обязателен: без него тест поднимет боевой майнер.

Правки, которые трогают железо (лимит мощности, кулер, схема питания), проверяйте
ещё и живьём и приложите результат `tools/check_restore.py compare`: после выхода
приложения настройки ПК должны совпасть с исходными.

## Стиль

- Интерфейс русский, подписи короткие; стили — инлайн QSS рядом с виджетом.
- Комментарии объясняют **почему**, а не «что»; замеры — с датой и цифрами.
- Не переписывайте `engine/minerctl.py` без нужды: это копия CLI-движка.
  Если меняете движок в `W:\mining\scripts`, обновите копию и напишите об этом в PR.
